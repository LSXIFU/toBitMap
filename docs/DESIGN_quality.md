# 转换质量提升 + 艺术字生成（设计）

> 状态：**设计待确认，不含实现**。本文件只描述方案与验收断言，不动代码。
> 约束：单页纯前端、无构建、双击 `file://` 可用；沿用现有四布局 codec 与回归预言机。
> 基线：`script.js` 读于 3757 行版本（含 `window.toBitMap` 对外 API）。**源码在并行演进，行号会漂移——定位一律以函数名为准，行号只作导航。**

---

## 0. 结论（先给可执行的答案）

**先做这三件**（按落地顺序，前两件共用一个挂点，第三件是新 tab）：

1. **覆盖率守恒阈值**（`computeCoverageThreshold`）——把"阈值"从亮度刻度改成**墨量刻度**。
   解决"换字号就得重调滑杆、同一串字在不同尺寸下粗细不一"。
2. **目标尺度反锐化**（降采样**之后**、二值化之前，`values` 上做 3×3 非锐化）——把小字笔画边缘的灰度斜率抬起来，降低阈值抖动导致的断笔/粘连。
3. **文字层**（文本 → 逐字渲染 → 字符切分 → 紧凑排布 + 居中 → 统一收尾）——这是"艺术字工具不好用"的**主因**，而不是滤镜不够花。

**明确不做**：Canny 全套（Sobel 幅值 + 单阈值已足够，见 §3.7 实测）、骨架化默认开启（16px 上会塌字）、线性光/gamma 校正默认关闭（实测减墨 8~31%，只有与覆盖率阈值 `v*(c)` 同时使用才闭合，见 §3.10）、边缘保持降采样（浏览器 high-quality 降采样实测就是面积平均，`std=0`）、以及"十几个风格滑杆"。

### 1.2 必须知道的六个事实

**F1｜"二值化只在一处"目前是语义上的，不是字面上的。**
`binarizeImageData()`（155）决定灰度→0/255；`packBitmapBytes()`（697）又按 `data[..] > 128`（712 行）判一次。对已经是 0/255 的输入这次判定是**恒等**（255→1，0→0），所以现在没有分叉风险。**推论**：新增的任何"二值化后"算子，只要输出严格是 `{0,255}`，就仍然只穿过一次真正的灰度判决，不破坏不变量。若某个算子输出了中间灰度（例如二值化后再做一次模糊），它就会**偷偷把 `packBitmapBytes` 变成真正的第二判决点**——这是本设计的第一条红线。

**F2｜预览、C 代码、导出共用同一个 `processedImageData`，但导出是"从源重算"而非复制预览。**
有 **7 个** 发射点（`processBinaryImage` 直接调用 + 不经它的取源路径）：

| # | 位置 | 行 |
|---|---|---|
| 1 | `processImage()` | 1670 |
| 2 | `processVideoFrame()` | 1729 |
| 3 | `exportVideo()` 逐帧 | 2988 |
| 4 | `exportRawImage()` 图片分支 | 3060 |
| 5 | `exportRawVideo()` 逐帧（`processNextRawFrame`） | 3159 |
| 6 | 手绘：`processDrawCanvas()` / `exportRawImage()` 的 draw 分支 | 1887 / 3071 |
| 7 | 对外 API：`toBitMapApi.binarize()`（`encode` / `encodeCanvas` 都经过它） | 3637 |

第 6 条**不经过** `processBinaryImage()`：它直接把 `drawCanvas` 画进目标尺寸，靠 `packBitmapBytes` 的 `>128` 完成唯一一次判定。
第 7 条是 `vm` 加载的纯计算入口（`cli.mjs` 走这里）——**它和页面共用同一份实现**，所以新算子若只接在页面的取源链上，CLI 导出的字节就会和页面不一致。这是新增的、必须堵住的分叉点。
**推论**：新算子必须收进一个共用收尾函数，只改一处会让"预览好看、导出难看"。

**F3｜抖动模式下"阈值"不是阈值，而是亮度偏置。**
`binarizeImageData()` 中 Bayer 分支（165 行）：

```
bias = threshold - 128
on   = values[p] + bias > (M[y%n][x%n] + 0.5) * (255/(n*n))
```

Otsu 在这种图上实测给出 127~151（见附表），代入 `bias = -1~23` —— **自动阈值在 Bayer 模式下几乎是空操作**。Floyd 分支（184~212）用 `threshold` 做量化判决，但最后一位又按 `buf[p] >= 128` 落定（203 行）。
**推论**：艺术字不该走抖动路径；抖动只服务于连续调图像，且必须重新定义滑杆语义（见 §3.9）。

**F4｜alpha 被完全忽略，透明底的 AA 边缘会被当纯色。**
`buildMetricValues()`（122~150）只读 `data[i], data[i+1], data[i+2]`。浏览器 `getImageData` 返回**非预乘** RGBA。实测（Edge headless，48px 白字、透明底、64×64 画布）：

- 不透明 208 px，全透明 3638 px，**半透明 250 px（占 6.4%）**；
- 全透明像素 RGB **全为 0**；
- 半透明像素 RGB **全不为 0**（白字即 255）。

**推论**：透明底文字层 → 背景读成 0（=暗=bit 0），半透明 AA 边缘读成 255（=亮=bit 1）。**边缘的覆盖率信息在进入阈值前就丢了**，这正是"小字边缘一档一档跳"的物理原因。任何文字层必须先合成到确定的底色（黑或白），再进管线。

**F5｜手绘模式的取源把网格线一起采样了。**
`renderDrawSurface()`（1758）把 `#ddd` 网格画进 `drawCanvas`（1782~1794），`processDrawCanvas()`（1873，取源在 1887）用池内 ctx 的 `imageSmoothingEnabled=false`（299）做**最近邻**采样。实测（复刻 384×384、24px 网格、接近邻缩放到 N×N）：

| 目标 | 网格色(221)像素 | 纯白 | 纯黑 | 其他灰 | 总像素 |
|---|---|---|---|---|---|
| 16×16 | 0 | 244 | 12 | 0 | 256 |
| 32×32 | 0 | 976 | 48 | 0 | 1024 |
| **37×37** | 0 | 1108 | 48 | **213（15.6%）** | 1369 |
| 48×48 | 0 | 2196 | 108 | 0 | 2304 |

采样位置模型 `floor((x+0.5)·srcW/dstW)` 与实测**吻合 100%**。整数倍尺寸恰好落在格心（`24x+12`）所以干净；非整数倍就有 15.6% 的像素是网格与内容的混色。
**推论**：网格必须与内容分离（独立 overlay 或捕获时关网格），否则"任意尺寸"这条路永远有小噪点。文字层不要复用 `drawCanvas`。

**F6｜降采样已经是对的，不要再造算法。**
实测（Edge headless）：2px 周期棋盘 512→32，`imageSmoothingQuality='high'` 单步 → mean 127.0 / **std 0.0**；复刻 `drawSourceDownscaled` 的分步折半 → mean 127.0 / **std 0.0**；理论 16×16 盒式平均 → mean 128 / std 0。三者等价，说明浏览器 high-quality 降采样对倍率大的情况**已经在做面积平均**，没有摩尔纹。4000×3000 → 16 单步 `drawImage` **2.6 ms**。
**推论**："边缘保持降采样""gamma 校正超采样"这类改动没有可测的收益空间（详见 §3.12、§4.3）。

**F7｜现有回归只覆盖布局。**
`runBitmapSelfTest()`（3477）共 **167** 个断言：8 形体 × 5 图案 × 4 布局 = 160，加 2 条位序黄金值、3 条页模式黄金值、2 条真实管线往返。**没有一条图像域断言**。新增算子必须自带像素级断言，否则等于没有回归。

## 2. "现有艺术字工具不好搞"的具体化清单

每条都给**失败模式**和**可判定的判据**（判据都已用实测数据校准）。

| # | 痛点 | 失败模式（怎么坏） | 判据 |
|---|---|---|---|
| P1 | **字号一换，粗细就变** | Otsu 只看类间方差、不看面积。同一字 16px 与 64px 的墨量覆盖率能差 10 个百分点以上，表现为"16px 糊成一坨、32px 变细"。 | 同字在 16/24/32px 的 `ink/bbox` 面积比，极差 > 5pp |
| P2 | **阈值脆弱：动一格就断笔** | 小字笔画只有 1~2px，边界两侧灰度差小；阈值 ±16 就能翻掉 2% 的像素，视觉上是"某一笔断开/两笔粘上"。 | `t±8` 的翻转像素 > 1% |
| P3 | **抖动把字弄脏** | 对已经是二值的字形做 Bayer/Floyd，会在笔画边缘造出孤立点；再去噪又把笔画啃掉。 | 孤立点计数 > 0；且 3×3 去噪后墨量变化 > 15% |
| P4 | **字距和居中要手调** | 固定步进 = 字高，对拉丁/数字浪费 11~16% 宽度；居中靠肉眼加空格。 | 字间零列游程 < 1 像素；墨迹 bbox 中心与画布中心偏差 > 1 逻辑像素 |
| P5 | **同一套参数出不了统一的字重** | "正常/加粗"靠手动改阈值实现，换个字就得重调；1px 与 2px 笔画无法在同一尺寸下共存。 | 同一参数集下两个字的覆盖率差 > 5pp |
| P6 | **极性要手勾"反转黑白"** | 输入是"白底黑字"还是"黑底白字"决定 bit 语义，工具不判断；手绘、透明 PNG 尤其明显。 | 前景覆盖率 < 5% 或 > 95% 时判为极性反了（可自动纠正） |
| P7 | **多字没有数据结构** | 一张图 = 一个数组；多字只能手工拼图或导出多份再自己合并，没有字库/码表。 | 导出物里能否按字符索引取位图（有/无） |
| P8 | **风格不可复现、不可批量** | 观感全靠现场拖滑杆，没有可保存的参数集；批量 ZIP 只能全用一套参数。 | 同样输入两次运行是否逐字节相同（确定性） |
| P9 | **网格污染（手绘/复用画布时）** | 非 8 整数倍尺寸下 15.6% 像素是网格混色，二值化后成散点。 | 输出中"只由网格产生"的置位像素数 > 0 |
| P10 | **抖动下"自动阈值"是空操作** | `bias = t-128`，Otsu 给 127~151 → 偏置 -1~23，几乎不动。用户以为自动了，其实没生效。 | 切换抖动前后自动阈值结果差异 < 5 灰度级 |

## 3. 候选技术清单（13 条）

每条格式固定：**原理 → 公式/伪代码 → 代价 → 前端可行性 → 挂点 → 断言 → 失败模式**。
"挂点"取值：`取源前` / `降采样后·二值化前(灰度)` / `二值化内` / `二值化后(布尔)` / `布局前(权威缓冲)`。

### 3.1 覆盖率守恒阈值（面积分位数阈值）

- **原理**：字形的"视觉重量"由**墨量面积**（图像的一阶矩/零阶矩）决定，不由类间方差决定。Otsu 最大化 `ω_b·ω_f·(μ_b−μ_f)²`，与面积无关，因此同一字形在不同尺寸下会得到不同的覆盖率。把阈值改成"命中目标覆盖率的分位数"，就等于把判决面钉在等面积线上——这正是字体排印里"字重"的定义方式。
- **公式**：
  ```
  c*  = 目标覆盖率（细 0.26 / 常规 0.33 / 粗 0.40）
  hist[256] ← 度量值直方图（复用 buildMetricValues）
  cum[t] = Σ_{i≤t} hist[i] / N
  t* = min{ t : cum[t] ≥ c* }
  ```
- **代价**：`O(N + 256)`，与 Otsu 同量级（Otsu 实测在 256×128 上被 0.08ms 的打包成本淹没）。
- **前端可行性**：纯 TypedArray，无依赖；对 `individual` 阈值类型同样成立（其度量值只有 0/85/170/255 四档，分位数会跳到台阶上，需回退 Otsu 或用插值）。
- **挂点**：`二值化内`（替换阈值来源，不改 `binarizeImageData` 的判定逻辑）。
- **断言**：同一字体同一字，16/24/32px 的实测覆盖率与 `c*` 偏差 ≤ 1pp；Otsu 对照组极差 > 5pp。
  实测（微软雅黑，`c*` 取 64px 的 Otsu 覆盖率）：

  | 字 | Otsu 16/24/32/64px | Otsu 极差 | 覆盖率锁定 16/24/32px | 锁定后极差 |
  |---|---|---|---|---|
  | 电 | 50.8 / 42.7 / 38.2 / 39.9 % | **12.6pp** | 38.3 / 37.5 / 38.5 % | **1.0pp** |
  | 圖 | 49.6 / 60.2 / 52.6 / 57.8 % | **10.6pp** | 56.7 / 56.4 / 57.7 % | **1.3pp** |
  | 术 | 30.5 / 23.9 / 23.9 / 26.8 % | **6.6pp** | 22.7 / 25.7 / 25.0 % | **3.0pp** |
- **失败模式**：目标覆盖率与"内容是什么"无关——照片会被强行压到固定墨量，丢掉高光/阴影结构。**所以它只能给文字层（或用户显式选"艺术字"模式）用，照片仍走 Otsu。**另外分位数阈值在直方图有长尾（大面积渐变背景）时会跳到背景上，需先按 §3.4 或先裁到墨迹 bbox。

### 3.2 目标尺度反锐化（unsharp on target scale）

- **原理**：降采样是低通，笔画边缘的灰度斜坡被拉平；边缘位置对阈值的敏感度正比于 `1/|∇I|`——斜率越小，阈值一动边界就滑得越远。反锐化把高频（`I − 低通(I)`）加回去，抬高边缘斜率，把边界"钉"在过零点附近。**关键在尺度**：任何频率高于**降采样后** Nyquist 的预增强，都会被随后的面积平均按 `sinc` 零点吃掉。
- **公式**：
  ```
  y(x,y) = clamp( x(x,y) + a·( x(x,y) − box3x3(x)(x,y) ), 0, 255 ),  a ∈ [1,3]
  ```
- **代价**：实测 `1.14 ms @256×128`（3×3 邻域 9 次读 + 1 次写，`O(9N)`）；32×32 上 0.29ms。
- **前端可行性**：`values`（Float32）上原地做，零额外 ImageData；不需要 `ctx.filter`（`file://` 下 Safari 行为不一致）。
- **挂点**：`降采样后·二值化前(灰度)`——具体是 `buildMetricValues()` 之后、判决之前。
- **断言**：`t±16` 的翻转像素比例下降 ≥ 30%，同时墨量变化 ≤ 5%。
  实测（`a=2`）：

  | 字/尺寸 | 原始翻转率 | 锐化后 | 墨量 |
  |---|---|---|---|
  | A 16px | 2.2% | **1.3%**（a=3 时 0.9%） | 78 → 74 |
  | 艺 16px | 1.7% | **0.4%** | 77 → 76 |
  | 艺 32px | 1.8% | **0.6%** | 334 → 327 |

  **反证**（必须写进实现注释）：把同一 DoG 放在**降采样之前**（源 400px 上做 σ1=1/σ2=3、乘 1.5），16/24px 的翻转率 2.2%→2.2%、1.7%→1.7%，**完全没有变化**。预增强被 8 倍面积平均抹平了。
- **失败模式**：`a > 3` 出现振铃——笔画两侧各出现一圈浅灰带，阈值化后变成"双线/描边"；对本身已有硬边、低分辨率的 logo 会整体加粗 1px。必须夹 `a ∈ [0,3]` 且默认 2。

### 3.3 文字层：字符切分 + 紧凑排布 + 居中

- **原理**：可读性由"字面框（ink bbox）+ 字间距"决定，二者都应与字号成比例，而不是与"全角 advance"成比例。固定步进（= 字高）对 CJK 尚可，对拉丁/数字/标点浪费 11~16% 的横向预算——在 128px 宽的 OLED 上这就是"少显示一个字"。
- **公式**：
  ```
  逐字渲染 → 量 ink bbox 宽 w_i（不是 advance）
  g  = max(1, round(H/16))            // 字间距：1px @16，2px @32
  W  = Σ w_i + (N−1)·g
  W' = ceil(W/8)*8                    // 必须向上取到字节边界，padding 位为 0
  x0 = floor((Wtarget − W)/2)         // 再对齐到字节/像素，避免半像素
  ```
- **代价**：`O(N·H²)` 渲染，可忽略；排版本身是整数运算。
- **前端可行性**：离屏 canvas + `fillText` + `getImageData` 量 bbox；`measureText()` 给的是 advance，**不能**当 ink 宽度用（左右留白差异可达 15%）。
- **挂点**：`取源前`（文字层自己产出 ImageData 后，再汇入统一收尾）。
- **断言**：
  1. 每个字符的 advance 区间内，ink 的列投影非空；
  2. 相邻字符之间存在 ≥1 个全零列（`g ≥ 1`）；
  3. 整幅墨迹 bbox 的水平中心与画布中心偏差 ≤ 1 逻辑像素；
  4. 总宽 `W'` 是 8 的倍数，且 `canonicalBufferSize(W',H)` 与导出的 `bytes.length` 相等。
  实测紧凑收益（`艺术字体ABC`，按字号渲染后各自取 bbox）：16px 112→98px（省 12%）、24px 168→150（省 11%）、32px 224→189（省 16%）。
- **失败模式**：**不能用"连通域数 == 字符数"做断言**——`艺` 的草头与下部、`术` 的点、`i/j` 的点本来就是分离的（实测 艺/术 在 16~48px 上都是 2 个连通域）。断言必须按"字符 advance 区间"而不是全局连通域。

### 3.4 Sauvola 局部自适应阈值

- **原理**：判决面随局部均值与局部对比度移动：`T = m·[1 + k(σ/R − 1)]`。在暗背景区 `m` 小 → `T` 自动下降，等价于把光照的低频分量除掉（同态滤波的一阶近似）。全局 Otsu 是**单一平面**，遇到渐变/暗角必然切掉一侧。
- **公式**：
  ```
  m(x,y), σ(x,y): w×w 窗口均值/标准差（积分图 O(1) 求）
  T = m·[1 + k(σ/R − 1)],  k = 0.2, R = 128, w = 15
  b = ( v < T ) ? 1 : 0
  ```
- **代价**：积分图 `O(N)`；`1.17 ms @256×128`（实测）。内存：两张 `(W+1)(H+1)` Float64，256×128 约 0.53MB；**1024×1024 时 16.8MB**（`maxBitmapSize` 上限，1024 行 18）——这是必须写进代码注释的上限。
- **前端可行性**：纯 TypedArray，无依赖。
- **挂点**：`二值化内`（`binarizeImageData` 的一个新分支，不改 `packBitmapBytes`）。
- **断言**：合成"文字压在 60→200 横向渐变上"，误分类率（对硬边 GT）≤ 3%。
  实测：Otsu **40.0 / 41.0 / 40.2%**（16/32/64px），Sauvola **2.2 / 0.8 / 0.7%**，Niblack 9.3 / 4.8 / 2.6%。
  平坦白底上与 Otsu 的判决差异 ≤ 2%（保证不破坏现有照片效果）。
- **失败模式**：
  - `w` 必须远大于笔画宽度：16px 位图上 `w=15` 覆盖全幅 → 退化成全局阈值；`w=3` 时 `σ` 由噪声主导 → 纯色区 `σ≈0` → `T≈m(1−k)`，纸白被判成前景（**"白纸变脏"**）。
  - 因此限制：仅当 `min(W,H) ≥ 32` 且用户显式选择；默认不启用。

### 3.5 形态学：只删孤立点（open 的单点特例）

- **原理**：笔画是连通的——任何真笔画像素至少有一个 8 邻域邻居。8 邻域全空的置位像素只能来自采样噪声或抖动残渣。完整的 3×3 开运算（先腐蚀再膨胀）会削掉 1px 笔画；"只删孤立点"是可证明的**最小干预**。
- **公式**：
  ```
  若 b=1 且 Σ_{8邻域} b = 0  → b=0      （对背景对称处理：Σ=8 → 1）
  其他像素一律不动
  ```
- **代价**：`O(8N)`，实测 3×3 众数版 0.32ms@128×64 / 0.86ms@256×128；单点版更省（只读 8 邻居、只在命中时写）。
- **前端可行性**：布尔掩码上跑，纯整数。
- **挂点**：`二值化后(布尔)`。
- **断言**：孤立点计数从 >0 变 0，且 `diff(op(input), input)` 的像素集合**恰好等于**孤立点集合（逐位比对，证明"只删点、不动笔画"）。
- **失败模式**：真正的单像素细节（句号、`i` 的点、装饰点）会被当噪声删掉。缓解：仅当孤立点数 < 面积 0.5% 时执行，且给开关。
  反例实测：用 3×3 **众数**滤波（不是单点版）去噪，`艺` 16px 墨量 82→63（**−23%**），笔画被啃掉——这就是"形态学开闭去噪"在小字上的真实代价，不能作为默认。

### 3.6 距离变换描边 / 外发光

- **原理**：外扩 r 像素 = 形态学膨胀 = `{p : dist(p, ink) ≤ r}`。用两遍 chamfer(3,4) 近似欧氏距离（最大误差约 8%），比"8 方向模板扫"各向异性小，比精确 EDT 便宜一个量级。视觉上"描边"就是给字形加一圈等距壳，等距性直接由距离变换保证。
- **公式**：
  ```
  初始化 d(p) = 0 (背景) / ∞ (墨迹)
  前向：d = min(d, d[y-1,x]+3, d[y-1,x±1]+4, d[y,x-1]+3)
  后向：对称
  grow = { p : d(p) ≤ 3r }        // 正交 3 = 1px，对角 4 ≈ 1.41px
  ```
- **代价**：两遍 `O(N)`；实测 0.17ms@128×64、0.54ms@256×128；Float32 `4N` 字节（1024² → 4.2MB）。
- **前端可行性**：纯 TypedArray。**必须在逻辑位图上做**，不能在布局字节流上做——页/列布局下"右邻居"落在别的字节甚至别的页，跨字节邻域不可用。
- **挂点**：`二值化后(布尔)`。
- **断言**：`r=1` 时，原置位像素的 8 邻域全为 1；新增像素集合 == `8邻域 \ 原集合`（逐位相等）。
- **失败模式**：16px 上笔画宽约 1~2px，1px 外扩使墨量 **+167%~+212%**（实测 A/艺），孔洞（`电` 的 4 个）会被填死 → 字变"糊块"。使用限制：`r=1` 且仅在 `H ≥ 24` 时开放；或先按 §3.8 细化再描边（线稿风格）。

### 3.7 Sobel 轮廓字（不做 Canny）

- **原理**：轮廓 = 梯度幅值的脊线。Canny = 高斯平滑 + 非极大值抑制 + 双阈值滞后。但在 8~32px 的字上笔画只有 1~3px，σ≈1 的高斯已经把笔画抹平，NMS 反而把本已很薄的轮廓切断。**实测在这类图上 Sobel 幅值 + 单一相对阈值就能给出闭合轮廓**（端点计数 0~2），Canny 的额外两步没有收益。
- **公式**：
  ```
  gx = [1 0 -1; 2 0 -2; 1 0 -1] * I ,  gy = 转置
  mag = sqrt(gx² + gy²)
  edge = mag > 0.25 * max(mag)
  ```
- **代价**：0.09ms@128×64、0.46ms@256×128。
- **前端可行性**：纯 TypedArray；`file://` 下也可用 `ctx.filter` 但行为不稳，不用。
- **挂点**：`降采样后·二值化前(灰度)`（在灰度上取边，产出布尔轮廓后**跳过**阈值判决）。
- **断言**：轮廓闭合 → 轮廓掩码的"洞"数等于原墨迹的洞数（`A`=1，`电`=4）。
  实测端点（度=1 的像素）计数：`A` 16/32/64px = 0/2/2；`艺` = 0/0/2；`电` = 0/0/2。边缘像素约为墨量的 1.5 倍。
- **失败模式**：阈值按 `max(mag)` 取相对值会随对比度漂移（低对比输入会整幅成边）；边缘宽度不均（Sobel 幅值在斜边更宽）→ 想要"均匀 1px 轮廓"仍需 NMS 或骨架化。作为**风格**可接受，作为"提升清晰度"不可接受。

### 3.8 Zhang-Suen 骨架化

- **原理**：反复删除满足"8 邻域数 2~6、0→1 穿越数 A=1、且不破坏端点/角点模板"的边界像素，直到不动点；结果是无 2×2 全 1 块的 1px 中轴（拓扑保持的细化）。
- **公式**（两阶段，阶段二把条件 `P2·P4·P6` 换成 `P2·P4·P8`）：
  ```
  B = Σ P2..P9        ∈ [2,6]
  A = #{ i : P_i=0, P_{i+1}=1 } = 1
  stage1: P2·P4·P6 = 0 且 P4·P6·P8 = 0
  stage2: P2·P4·P8 = 0 且 P2·P6·P8 = 0
  ```
- **代价**：**最贵**——3.55ms@256×128、1.21ms@128×64、0.56ms@32×32；迭代 2~5 次（16~48px 实测）。
- **前端可行性**：纯 TypedArray；需要 `Uint8` 工作副本 + 删除列表。
- **挂点**：`二值化后(布尔)`。
- **断言**：输出无 2×2 全 1 块（实测 0）；8 连通域数不变（实测 艺 2→2、A 1→1）；骨架像素 < 墨量 50%。
- **失败模式**：16px 上骨架只剩 41~63 像素，`电` 的内框塌成"井"，CJK 多笔画交叉处粘成团。**它不能作为"提升清晰度"的手段**，只能作为"单线/线稿"风格，且建议只在 `H ≥ 24` 开放。

### 3.9 局部抖动（只在灰阶过渡区抖，硬边不抖）

- **原理**：抖动是用空间频率换灰阶。已经确定的笔画内部（覆盖率≈1）和纯背景（≈0）没有灰阶要表达，在那里抖动只会产生孤立点（实测 Bayer4 在 16px `艺` 上产生 6 个孤立点）。只在 `c ∈ (0.05, 0.95)` 的过渡带抖动，可以同时保住"边缘干净"和"中间调有层次"。
- **公式**：
  ```
  c = v/255
  if c ≤ 0.05 → 0 ;  if c ≥ 0.95 → 1
  else → on = ( c·255 + (t−128) > (M[y%n][x%n]+0.5)·255/n² )
  ```
- **代价**：与现有 Bayer 同量级（0.15ms@256×128），加一次除法。
- **前端可行性**：直接改 `binarizeImageData` 的 Bayer 分支。
- **挂点**：`二值化内`。
- **断言**：孤立点计数 = 0（原 6）；笔画内部像素与"纯阈值"结果逐位相同。
- **失败模式**：软边照片会在过渡带边界出现可见"接缝带"（一半抖动、一半硬边）。需要把硬门限换成斜坡（`0.02~0.08` 线性过渡），否则接缝比噪点更难看。

### 3.10 超采样文本渲染（4× 渲染 + 面积平均）与 gamma 校正（默认关）

- **原理**：浏览器在目标尺寸给的 AA 是"一个像素一个覆盖率"，4× 渲染后 16:1 面积平均等于把覆盖率量化到 1/16 子像素，误差从 ±0.5/1 降到 ±0.03。
- **公式**：`font = H`（按目标字号渲染字宽，不是放大）；`canvas = 4H × 4H`；`BOX` 平均到 `H`。
- **代价**：16 倍像素的 `fillText`；H=16 时 64×64 = 4096 px，可忽略。
- **前端可行性**：离屏 canvas + `drawImage` 分步折半（复用 `drawSourceDownscaled` 的思路，但**不要**复用它——它接的是 DOM 源，文字层是程序化 canvas）。
- **挂点**：`取源前`。
- **断言**：与 1× 渲染相比，同一字的覆盖率差 ≤ 2%，bbox 尺寸一致。
- **失败模式**：hinting 在 4× 与 1× 下不同（advance 会变），若按 4× 的字宽排版，小字号下会挤。**必须按 1× 量 advance、按 4× 量 ink bbox**。
- **gamma 校正（同一候选的可选后半段）**：面积平均应当在**线性光**里做，否则 30% 覆盖率的暗笔画会被算成 178 灰，而不是 218 灰。
  ```
  L  = ((v/255 + 0.055) / 1.055)^2.4        // sRGB → 线性光
  L̄  = 面积平均(L) ;  v' = 255·(1.055·L̄^(1/2.4) − 0.055)
  ```
  实测代价：线性光平均让 16px 的墨量 **A 78→54（−31%）、艺 77→61（−21%）、术 78→72（−8%）**，并在 `A` 16px 上**新造出 18 个 1px 细笔画**（原为 0）。
  根因不是"细节变少"，而是**映射变了**：50% 覆盖率在 sRGB 平均下是 128，在线性光平均下是 **186**。因此必须同时把阈值换成覆盖率刻度：
  ```
  v*(c) = 255·(1.055·c^(1/2.4) − 0.055)      // c=0.5 → 186，c=0.33 → 155
  ```
  否则等于偷偷把字变细一档。**默认关**；只有在"同一字体 8~64px 全档字重一致"的要求下，与 §3.1 的覆盖率阈值同时开启才闭环。

### 3.11 字库打包（字符码表 + 偏移表 + 位数据）

- **原理**：多字输出需要"按索引取位图"。定宽字库（所有字同 W×H）可省偏移表：`offset = idx × bytesPerGlyph`。变宽字库需要 `uint16` 偏移表（小端）。位数据沿用 `row_msb`（行优先、MSB 在左），与现有 `packBitmapBytes` 的输出逐字节一致。
- **公式**：
  ```
  bytesPerGlyph = ceil(W/8) * H
  offset[i]     = Σ_{j<i} bytesPerGlyph_j          // uint16，超过 64KB 需 uint32
  charMap[]     = 码点数组（UTF-16 或 GB2312 子集）
  data[]        = 每个字的 canonical 字节串
  ```
- **代价**（实测算式）：

  | 字号 | B/字 | 26 字 | 100 字 | 350 字 |
  |---|---|---|---|---|
  | 16px | 32 | 0.9KB | **3.3KB** | 11.6KB |
  | 24px | 72 | 1.9KB | 7.2KB | 25.3KB |
  | 32px | 128 | 3.3KB | 12.7KB | 44.4KB |

  16px × 100 字 = 3.3KB，塞进 ESP32 的 flash 毫无压力；这就是为什么"16px 字库"值得做。
- **前端可行性**：`formatCHeader()` 的变体，字符串拼接 + `Uint8Array`。
- **挂点**：`布局前(权威缓冲)`——每个字先各自 `packBitmapBytes` 得 canonical，再串接，最后整体 `transferBits` 到目标布局。
- **断言**：`decode(encode(idx))` 与单字导出逐字节相等；偏移表严格单调；`data.length == Σ bytesPerGlyph`。
- **失败模式**：变宽字库若用定宽偏移会错位；`page_lsb` 下若把整幅字库当一张大图转，字与字之间会跨页共享字节 → **必须逐字编码后再拼接**（每字高为 8 的倍数时页内安全，H 非 8 倍数时按整字节补齐）。

### 3.12 边缘保持降采样（导向滤波 / 联合双边）

- **原理**：在降采样核里加权，使权重随灰度差衰减，避免跨边平均。
- **代价**：`O(N·r²)`，r=4 时已与 Sobel 同量级，r=8 时十倍。
- **结论**：**不做**。实测浏览器 high-quality 降采样在 2px 棋盘上给出 `std = 0`（完全面积平均、零摩尔纹），而 1bpp 的最终判决只关心"面积是否过半"。EP 滤波保住的中间灰度，在 `>128` 判决处被整体丢弃——收益不可测，属于典型的过度设计。

### 3.13 风格算子族：网点 / 斜线填充 / 点阵化 / 马赛克

四个算子共享一个前提：**它们是"风格"，不是"画质"**——每个都必须以"整条链固定参数"的形式作为预设提供，不能拆成滑杆。

- **原理**：
  - **网点（调幅网点）**：在边长 `s` 的方格内画半径 `r` 的实心点，令 `πr² = c·s²`，即 `r = s·√(c/π)`。点的**面积**编码局部覆盖率 `c`，而不是靠点的密度——所以任意尺寸下墨量守恒，不会出现 Bayer 的棋盘纹。
  - **斜线填充（hatch）**：沿方向 θ、间距 `p` 的平行线族与墨迹掩码求交，解析式 `((x·cosθ + y·sinθ) mod p) < w`，取 `w=1` 得 1px 线。因为是解析的，任意宽高下线距都均匀。
  - **点阵化（dot-matrix）**：每个逻辑像素替换为 `k×k` 子格的中心点（k=2/3），等价于 `×k` 上采样后按格心抽样，用于模拟 LED 点阵屏。
  - **马赛克**：`b×b` 块内先平均再判决；块边界必须对齐到 8 像素网格，否则跨字节撕裂。
- **公式/伪代码**：
  ```
  网点： for each cell(s): r = s*sqrt(c/pi); if dist(p, cellCenter) <= r → 1
  斜线： on = ((x*cos(t) + y*sin(t)) mod p) < 1
  点阵： out[x*k + k/2][y*k + k/2] = in[x][y]        // k=2 时格心偏移 1
  马赛克： c = mean(block b×b); on = c >= 0.5
  ```
- **代价**：网点/斜线/马赛克均 `O(N)`（网点可把 `√c` 打成 256 项查表）；点阵化 `O(k²N)` 但只写位，`k=2` 时是 4 倍写入、16 倍画布面积。
- **前端可行性**：纯整数/查表，无依赖；全部在**逻辑位图**上做（理由同 §3.6：布局字节流里没有"右邻居"）。
- **挂点**：网点/斜线/点阵 = `二值化后(布尔)`；马赛克 = `二值化后(布尔)` 的块平均也可以，但要在块内保留灰度才能平均 → 更稳的是 `降采样后·二值化前(灰度)`，按块求均值后判决。
- **断言**：
  - 网点：每个 `s×s` 格内 ink 像素数 = `round(c·s²) ± 1`（面积守恒）；
  - 斜线：输出与解析线族逐像素比对，差异 ≤ 1px（线宽）；
  - 点阵（k=2）：任意 2×2 块内至多 1 个置位，且置位坐标满足 `(x mod 2, y mod 2) = (0,0)`；
  - 马赛克：每个 `b×b` 块内像素值方差 = 0。
- **失败模式**：
  - 网点/斜线的周期一旦大于笔画宽度，**字会被吃掉**（16px 上笔画 1~2px，用 s=3 的网点几乎抹平）→ 限 `H ≥ 24` 且笔画宽 ≥ 2；
  - 点阵化把有效分辨率降到 `1/k`，16px 字只剩 8px 内容，等于自废——只适合本来就大的标题字（H ≥ 32）；
  - 马赛克块不对齐字节 → 跨字节撕裂；`page_lsb` 下尤其明显；
  - 四者都会让"字重"失真：因为覆盖率被量化到格/线，实测路径应与 §3.1 的覆盖率阈值**互斥**（风格链里不再二次调阈值）。

| 10 | 超采样渲染（+可选 gamma 覆盖率换算） | 覆盖率精度 +1/16；跨档字重一致 | 低 | gamma 需配 `v*(c)`，否则减墨 8~31% | 超采样随文字层；gamma 默认关 |
| 11 | 骨架化 | 单线风格 | **高**（3.55ms） | 小字塌字 | 只作风格，默认关 |
| 12 | 边缘保持降采样 | **无可测收益** | 高 | — | **不做** |

### 4.2 为什么只先做 3 个

- 1 和 2 **共用同一个挂点**（`buildMetricValues()` 之后、判决之前），一次改动同时解决"字重不一致"和"阈值脆弱"这两个体验上最刺眼的问题，且都能用像素断言证明生效。
- 3 不是滤镜，是**输入生成器**；P4/P6/P7（字距、居中、极性、多字）占了"艺术字工具不好用"的一半以上，而且不做它，前两项的收益只能靠用户手工摆字来兑现。
- 其余项要么是"风格"（描边/轮廓/骨架/网点），要么是"照片专用"（Sauvola），要么收益不可测（EP 降采样）。风格应该在排版稳定之后再加，否则会出现"字都排不齐，却有一堆滤镜"的典型失败产品。

### 4.3 反模式与过度设计风险（必须写进设计约束）

1. **叠硬门限越加越糟**：每引入一个算子就带来一个新的绝对阈值（孤立点面积比、轮廓 `0.25·max`、描边半径、抖动的 `0.05/0.95`）。三个以上绝对阈值交互后，用户无法解释"为什么这次糊了"，开发者也无法定位。约束：**每个算子最多 1 个参数，且必须有像素级断言；默认值必须让"不选任何风格"的输出与今天逐字节相同。**
2. **把风格做成十几个滑杆 = 把复杂度推给用户**。风格应以 **4~6 个预设**出现（正常/加粗/描边/轮廓/网点/细线），每个预设 = 固定算子链 + 固定参数；对外只暴露"字重（细/常规/粗）"和"风格"两个选择。
3. **在字节流上做图像处理**：页/列布局下相邻像素不在同一字节，跨字节/跨页邻域全部失效。所有形态学/距离变换只能在**逻辑位图**上做。
4. **用抖动"提升"二值文字质量**：抖动服务于连续调；字是二值的，抖动只会加噪点（P3）。
5. **为降采样再发明算法**：浏览器 high-quality 已经是面积平均（std=0 实测）。任何"更好的降采样"都必须先给出比 std=0 更好的指标，否则不做。
6. **gamma/线性光校正的陷阱**：实测线性光平均会把 16px 的墨量压掉 **8~31%**（A −31%、艺 −21%、术 −8%），并在 16px 上**新造出 18 个 1px 细笔画**（原为 0）。它改变的是"覆盖率→灰度"的映射，不是"细节量"。要用它就必须同时把阈值换算成覆盖率（50% 覆盖率在线性光下对应 sRGB ≈ 186，而不是 128）。这层复杂度换来的"跨字号一致性"，候选 1 已经用更直接的方式给出了。

## 5. 与现有不变量的关系（每个候选属于哪一类）

### 5.1 分类

| 类别 | 含义 | 候选 | 是否新增灰度→位判决 |
|---|---|---|---|
| A. 取源前 | 影响"画进临时 canvas 之前" | 3.3 文字层、3.10 超采样、F5 网格分离 | 否 |
| B. 降采样后·二值化前（灰度域） | 改 `values`/阈值 | 3.1 覆盖率阈值、3.2 反锐化、3.4 Sauvola、3.7 Sobel 轮廓 | 阈值类：否（只换阈值来源）；轮廓：是（直接用 `mag>thr` 定位，**跳过**阈值） |
| C. 二值化内 | `binarizeImageData` 的判决分支 | 3.9 局部抖动 | 否 |
| D. 二值化后（布尔 ImageData） | 输入输出都是 `{0,255}` | 3.5 去孤立点、3.6 描边、3.8 骨架化 | 否（幂等穿过 `>128`） |
| E. 布局前（权威缓冲） | `Uint8Array` 位域 | 3.11 字库拼接 | 否 |
| F. 布局后 | `transferBits` 之后 | **禁止任何算子** | — |

### 5.2 五条不变量（写进代码注释）

- **I1｜灰度→逻辑位的判决仍然只有一处**：`binarizeImageData()`（含新阈值来源）。`packBitmapBytes()` 的 `>128`（712）只对 `{0,255}` 幂等。**D 类算子的输出必须是严格 0/255，禁止输出中间灰度。**
- **I2｜D 类算子的形式化判据**：`packBitmapBytes(op(x))` 必须逐字节等于"把 `op(x)` 的布尔掩码直接打包"。这条断言能一次性抓住"算子偷偷改成了灰度"。
- **I3｜`transferBits` / `packBitmapBytes` 的位序语义不许动**。新算子全部作用在 `transferBits` 之前，因此四布局往返与 `runBitmapSelfTest()` 的 167 条断言天然不受影响——但必须重跑并保持全绿。
- **I4｜七个发射点共用一个收尾函数**（§1.2 F2 的表）。收尾函数之外的地方不许再调用算子。特别注意第 7 条：`toBitMapApi.binarize()`（3637）是 `cli.mjs` 的入口，收尾算子必须在 `processBinaryImage()` 内部完成接入，才能同时覆盖页面与 CLI。
- **I5｜默认关闭即向后兼容**：所有算子默认参数必须使输出与 v1.4 逐字节相同（用同一输入做 git 前后对比，见 §7 Step1）。

## 6. 艺术字的最小可用模型

### 6.1 输入（4 个控件，不是 14 个）

| 控件 | 取值 | 说明 |
|---|---|---|
| 文本 | 任意字符串 | 逐字渲染，不做连字/kerning（`file://` 下 `measureText` 的 kerning 不可控） |
| 字高 H | 8~64 | 直接映射到逻辑像素；宽度由排版自动决定，也可手动夹到 128/256 |
| 字重 | 细 0.26 / 常规 0.33 / 粗 0.40 | 就是覆盖率阈值 `c*`（§3.1） |
| 风格 | 正常 / 描边 / 轮廓 / 细线 | 固定算子链，不给参数 |

极性：**自动**。渲染后统计前景覆盖率，若 `> 0.5` 且背景是纯色，则判定输入是"反相"，自动翻转一次（对应 P6），不暴露给用户。

### 6.2 处理顺序（这就是"艺术字管线"）

```
① 离屏 canvas（4H 高，白底，无网格）   ← F5：不复用 drawCanvas
② 逐字 fillText，量 ink bbox → w_i     ← 3.10 超采样；advance 按 1× 量
③ 紧凑排布 + 居中 → W'（8 的倍数）
④ 一次性 drawImage 到 W'×H（面积平均，平滑开）   ← 复用 drawSourceDownscaled 的折半思路
⑤ buildMetricValues → 反锐化（a=2）              ← 3.2，B 类
⑥ 阈值 = 覆盖率阈值(c*, 字重)                    ← 3.1，B 类
⑦ 风格算子（按预设；默认空）                      ← D 类
⑧ 只删孤立点（默认开，阈值 0.5% 面积）            ← 3.5，D 类
⑨ 收尾：putImageData 预览 + scheduleCodeGeneration ← 与图片模式同一条路
```

### 6.3 多字导出（第 2 阶段）

- 单张：沿用 `formatCHeader()`（724），零改动。
- 字库：`charMap[]` + `offset[]`（uint16）+ 每字 canonical 数据；逐字 `packBitmapBytes` 再串接，最后 `transferBits` 整体转布局（§3.11）。
- 不做的：可变字重字库、抗锯齿字库（1bpp 没有灰阶）、字库压缩（RLE 收益 < 20%，加解码复杂度不值）。

## 7. 实施顺序与验收

**Step 1（纯重构，不改像素）**：新增 `applyBitmapFinish(imageData, opts)`，内部为空操作；在六个发射点接入。
验收：`window.bitmapSelfTest()` 167 条全绿；对同一张测试图，改前/改后导出的 `.h` **逐字节相同**（`git stash` 前后 diff）。

**Step 2（画质，图片模式先落地）**：`computeCoverageThreshold()` + `sharpenMetric()`，接到图片/视频链路，UI 只加"反锐化 0~3"一个滑杆（默认 2）。
验收：§3.1 的覆盖率极差 ≤ 3pp；§3.2 的翻转率下降 ≥ 30% 且墨量变化 ≤ 5%；默认参数下关闭滑杆（=0）时输出与 Step 1 逐字节相同。

**Step 3（文字层）**：新 tab + 排版 + 统一收尾。
验收：§3.3 的四条断言全过；导出 `.h` 的 `bytes.length == layoutBufferSize(W',H,fmt)` 对四种布局都成立。

**Step 4（去噪/抖动）**：`removeIsolatedBits()` + 过渡带抖动。
验收：孤立点归零且 `diff` 集合等于孤立点集合；笔画内部像素不变。

**Step 5（风格）**：描边（`growBits`）、轮廓（`edgeBits`）。每个风格一条断言（§3.6、§3.7）。

**Step 6（字库）**：`formatGlyphTable()` + 导出按钮。

**新增自检（建议加进页面，和 `runBitmapSelfTest` 并列）**：`window.bitmapQualitySelfTest()`，用合成样本（不是外部图片）跑 §3 的断言，至少覆盖：

```
1. 覆盖率锁定：16/24/32px 的 c 与 c* 差 ≤ 1pp
2. 反锐化：t±16 翻转率下降 ≥ 30%，墨量变化 ≤ 5%
3. 幂等性：packBitmapBytes(op(x)) === packBits(op 掩码)
4. 去孤立点：diff 集合 == 孤立点集合
5. 描边：新增集合 == 8邻域 \ 原集合；原集合 8 邻域全 1
6. 轮廓：洞数守恒（A=1，电=4）
7. 排版：相邻字符间存在 ≥1 个全零列；bbox 居中偏差 ≤ 1px
8. 兼容：默认参数下，输出与基线逐字节相同
```

## 8. 明确不做（本批）

- Canny 全套（高斯 + NMS + 双阈值滞后）：实测 Sobel 幅值 + 单阈值已能给闭合轮廓（端点 0~2），Canny 在 8~32px 上只会把笔画抹平。
- 骨架化作为"清晰度"手段：16px 上塌字，只能作"细线"风格。
- 线性光/gamma 校正：减墨 8~31%，需配套阈值换算，收益与候选 1 重叠。
- 边缘保持降采样（导向/双边）：浏览器已是面积平均，无可测收益。
- 神经网络超分/去噪：`file://` 下不能保证模型权重可加载（无构建、不能 fetch 本地 bin 之外的文件），且与"离线单文件"约束冲突。
- 自动布局（自动换行、自动字距学习）、可变字重字库、字体子集化。
- 任何在布局字节流上的图像算子。

### C.1 采样方式：超采样必做，但倍率要按尺寸选

对照物 = 16× 超采样面积平均后二值化的结果（最接近真实字形）。IoU 越大越保真；
翻转率 = 阈值 `t±16` 时会变色的像素占比，越小越抗调参。

| 方法 | IoU（A/艺/术 × 16/24px） | 翻转率 | 备注 |
|---|---|---|---|
| 直接 `fillText` 到目标字号 | **0.36 ~ 0.92** | 3.4 ~ 14% | 16px「术」只有 0.36：hinting 把笔画扭了 |
| ss2 | 0.64 ~ 0.95 | 2.2 ~ 9.6% | 不够，别用 |
| ss4 | 0.91 ~ 1.00 | 3.1 ~ 8.5% | 默认（H>32） |
| ss8 | 0.92 ~ 0.99 | 1.0 ~ 8.8% | 默认（H≤32）；更大尺寸收益 <1%，纯烧时间 |
| ss4 + 反锐化 a=2 | 0.82 ~ 0.98 | **1.0 ~ 4.0%** | 用保真换稳健 |

**修正**：§3.2 建议反锐化默认 `a=2`。实测 16px 汉字的 IoU 会从 0.94 掉到 0.82，
而翻转率改善只在"用户会去调阈值"时才有意义 —— 故文字层**默认关**，留给需要抗调参的人开。

### C.2 「紧凑排版省 11~16% 宽度」只在混排时成立

| 串 | 字号 | 内容宽 / 字数 | 相对字号 |
|---|---|---|---|
| 艺术字 | 24 | 24.7 | **+3%**（汉字墨迹 ≈ 字框，没有省宽余量） |
| ITL | 24 | 10.0 | −58% |
| WAVE | 24 | 18.0 | −25% |
| a | 24 | 11.0 | −54% |

**修正**：纯汉字串紧凑排布不省宽（墨迹本来就撑满 em）；它真正解决的是
「不等宽字 + 拉丁数字混排」时的参差与两侧留白。别拿这个数字去承诺汉字场景的收益。

### C.3 基线必须量化，否则混排一高一低

每个字形各自 `round(boxHeight/scale)` 会让墨迹下沿抖动 ±1~2px：
首次实现里「口A」的下沿差是 2px（应为 0）。改为先各自取整 ascent / descent，
再用二者之和定字形画布高度，下沿才严格落在基线上。

另：雅黑里「口」的 descent 实测为 2（24px），即它的下沿本来就低于基线 2px ——
这是字体设计，断言要写成「下沿差 = descent 差」，不能写成「下沿齐平」。

### C.4 排版不变量（仓库内自检，13 例）

宽度 8 对齐 / 高度 ≤ 字号 / 字号即渲染字号 / 字间有空白列 / 基线一致 / 反色互补 /
阈值单调 / 四种布局字节数 / 渲染确定性（同输入两次必须同一字节流）。
断言对象是**不变量**而非具体字形像素：字形随系统字体变，不变量不该变。
